# KeyFlow 代码结构

本文按当前实现说明代码结构。部署和交接优先看根目录 `交接文档.md` 与 `docs/镜像部署.md`。

## 1. 总体结构

```text
keyflow/
├── src/
│   ├── main.py
│   ├── worker_main.py
│   ├── gateway/
│   ├── interfaces/
│   ├── application/
│   ├── domain/
│   ├── infrastructure/
│   └── container/
├── config/
├── docker/
├── scripts/
├── tests/
└── docs/
```

当前推荐运行模式是：

```env
KEYFLOW_RUNTIME_MODE=local
```

子节点在 local 模式下使用 SQLite WAL，不依赖 PostgreSQL 和 Redis。`dev` 模式仍保留，用 PostgreSQL + Redis。

## 2. 运行入口

### 2.1 子节点 API

入口文件：

```text
src/main.py
```

实际创建应用：

```text
src/interfaces/api/app.py
```

启动命令：

```bash
uvicorn main:app --host 0.0.0.0 --port 8000 --app-dir src
```

职责：

- 暴露管理接口。
- 暴露分配接口。
- 暴露成功/失败上报接口。
- 启动时初始化 SQLite 或 PostgreSQL。
- 配置完整时，启动 Gateway 注册/心跳客户端。

### 2.2 子节点 worker

入口文件：

```text
src/worker_main.py
```

启动命令：

```bash
python src/worker_main.py
```

职责：

- 周期执行 `recover_cooldowns`。
- 周期执行 `refresh_keys`。
- 不提供 HTTP 接口。
- 与 API 共用 `.env` 和同一份数据存储。

### 2.3 Gateway

入口文件：

```text
src/gateway/main.py
src/gateway/app.py
```

启动命令：

```bash
uvicorn gateway.main:app --host 0.0.0.0 --port 8001 --app-dir src
```

职责：

- 子节点注册。
- 子节点心跳。
- 节点列表。
- 节点能力聚合。
- 管理请求转发到指定子节点。

Gateway 不做 key 分配。key 分配发生在子节点 API。

## 3. 分层职责

### 3.1 `domain/`

纯业务核心，不依赖 FastAPI、SQLAlchemy、Redis、SQLite。

```text
src/domain/
├── entities/
│   └── api_key.py
├── value_objects/
│   ├── key_pool.py
│   ├── key_status.py
│   └── provider.py
├── services/
│   ├── scheduler.py
│   ├── scorer.py
│   └── state_machine.py
├── repositories/
│   └── key_repository.py
└── exceptions/
    └── domain_exceptions.py
```

核心文件：

- `api_key.py`：Key 领域实体，保存 provider、credential、pool、状态、成功/失败计数、冷却时间、模型列表、可用性缓存等。
- `key_status.py`：状态枚举，包括 `pending`、`available`、`rate_limited`、`cooldown`、`disabled_upstream`、`disabled_admin`、`disabled_report`、`exhausted`。
- `scheduler.py`：对候选 key 排名。
- `scorer.py`：计算 key 分数。
- `state_machine.py`：根据上报结果驱动状态变化。
- `key_repository.py`：仓储和分配存储抽象接口。

### 3.2 `application/`

应用层负责编排用例。

```text
src/application/
├── commands/
├── queries/
└── services/
    ├── key_service.py
    └── model_alias_resolver.py
```

核心文件：

- `key_service.py`：KeyFlow 最核心应用服务，串起仓储、分配存储、调度器、状态机和 provider 插件。
- `model_alias_resolver.py`：读取 `config/model_aliases.yaml`，把统一模型名映射到 provider 原生模型名。

`KeyService` 负责：

- 创建 key。
- 更新 key。
- 删除 key。
- 移动 key pool。
- 按 provider 分配 key。
- 按 model 分配 key。
- 成功/失败上报。
- 刷新 key 可用性。
- 恢复冷却状态。

### 3.3 `interfaces/`

HTTP 表达层和 worker 支撑代码。

```text
src/interfaces/
├── api/
│   ├── app.py
│   ├── deps.py
│   └── routes/
│       ├── admin.py
│       ├── allocate.py
│       ├── health.py
│       └── report.py
├── middleware/
│   └── auth.py
├── schemas/
│   ├── request.py
│   └── response.py
└── workers/
    ├── background.py
    └── gateway_client.py
```

职责：

- FastAPI app 工厂。
- 路由注册。
- 请求和响应模型。
- `X-Internal-Key` 鉴权。
- worker 循环。
- 子节点向 Gateway 注册和心跳。

主要接口：

- `GET /health`
- `GET /api/providers`
- `POST /api/providers/{provider}/keys`
- `GET /api/providers/{provider}/keys`
- `PUT /api/keys/{key_id}`
- `DELETE /api/keys/{key_id}`
- `POST /api/internal/allocate-key`
- `POST /api/internal/allocate-by-model`
- `POST /api/internal/report-success`
- `POST /api/internal/report-error`

### 3.4 `infrastructure/`

外部依赖实现层。

```text
src/infrastructure/
├── cache/
├── config/
├── db/
├── logging/
└── plugins/
```

职责：

- SQLite / PostgreSQL session。
- 数据库模型。
- 仓储实现。
- local 模式分配存储。
- dev 模式 Redis/Lua 分配存储。
- 配置读取。
- provider 插件实现。

重要文件：

- `config/settings.py`：读取 `.env`。
- `db/models.py`：数据库表模型。
- `db/repository_impl.py`：Key 仓储实现。
- `db/sqlite_session.py`：local 模式 SQLite session。
- `db/sqlite_bootstrap.py`：local 模式 SQLite 初始化。
- `cache/sqlite_key_cache.py`：local 模式分配存储。
- `cache/redis_client.py`：Redis 客户端。
- `cache/key_cache.py`：Redis 分配存储。
- `cache/composite_key_cache.py`：dev 模式 Redis + DB 组合分配存储。
- `plugins/base.py`：provider 插件抽象。
- `plugins/providers/`：具体 provider 插件。

### 3.5 `gateway/`

Gateway 控制面。

```text
src/gateway/
├── app.py
├── config.py
├── main.py
├── models.py
├── node_client.py
├── repository.py
├── schemas.py
├── service.py
└── url_validation.py
```

职责：

- 保存节点注册信息。
- 接收心跳。
- 判断节点状态。
- 聚合 provider 能力。
- 转发管理接口到子节点。

Gateway 使用 `.env.gateway`，不使用子节点 `.env`。

### 3.6 `container/`

依赖注入装配。

```text
src/container/container.py
```

根据 `KEYFLOW_RUNTIME_MODE` 组装不同实现：

- `local`：SQLite repository + `SqliteKeyCache`。
- `dev`：PostgreSQL repository + Redis + `CompositeKeyCache`。

同时注册：

- `KeyScorer`
- `KeyScheduler`
- `KeyStateMachine`
- `ProviderRegistry`
- 所有 provider 插件
- `ModelAliasResolver`
- `KeyService`

## 4. local 与 dev 模式差异

| 模式 | 数据库 | 分配存储 | 默认推荐 |
| --- | --- | --- | --- |
| `local` | SQLite WAL | SQLite 分配存储 | 是 |
| `dev` | PostgreSQL | Redis + Lua + DB 兜底 | 否 |

local 模式配置：

```env
KEYFLOW_RUNTIME_MODE=local
LOCAL_SQLITE_PATH=/data/keyflow.db
```

dev 模式配置：

```env
KEYFLOW_RUNTIME_MODE=dev
DATABASE_URL_READ=postgresql+asyncpg://...
DATABASE_URL_WRITE=postgresql+asyncpg://...
REDIS_URL=redis://...
```

当前交接和生产推荐 local 模式。

## 6. 修改代码时看哪里

| 需求 | 优先看 |
| --- | --- |
| 新增或修改 HTTP 接口 | `src/interfaces/api/routes/`、`src/interfaces/schemas/` |
| 修改分配流程 | `src/application/services/key_service.py` |
| 修改评分规则 | `src/domain/services/scorer.py` |
| 修改排序选择 | `src/domain/services/scheduler.py` |
| 修改错误上报状态变化 | `src/domain/services/state_machine.py` |
| 修改 key 字段 | `src/domain/entities/api_key.py`、`src/infrastructure/db/models.py` |
| 修改 local 存储 | `src/infrastructure/db/sqlite_*`、`src/infrastructure/cache/sqlite_key_cache.py` |
| 修改 dev Redis 分配 | `src/infrastructure/cache/`、`src/infrastructure/cache/lua/` |
| 新增 provider | `src/infrastructure/plugins/providers/`、`src/container/container.py` |
| 修改 Gateway | `src/gateway/` |

- 涉及 local/dev 存储差异时，补对应集成测试。
