# 生产镜像 tar 分离部署

生产部署分为两个镜像、两类服务器：

- 调度服务镜像：`keyflow-gateway:prod`，部署到调度服务器，只启动 `keyflow-gateway`。
- 子节点镜像：`keyflow-node:prod`，部署到每台子节点服务器，启动 `keyflow-api` 和 `keyflow-worker`。

两个镜像使用同一个 Dockerfile 构建，但以不同镜像名、不同 tar 包交付，部署时不会混在同一台服务器启动。

## 1. 开发机分别构建两个 tar

Linux / macOS:

```bash
./scripts/build_gateway_image_tar.sh
./scripts/build_node_image_tar.sh
```

Windows:

```bat
scripts\build_gateway_image_tar.bat
scripts\build_node_image_tar.bat
```

默认输出：

```text
dist/keyflow-gateway-prod.tar
dist/keyflow-node-prod.tar
```

可通过环境变量统一修改标签：

```bash
KEYFLOW_IMAGE_TAG=2026-06-01 ./scripts/build_gateway_image_tar.sh
KEYFLOW_IMAGE_TAG=2026-06-01 ./scripts/build_node_image_tar.sh
```

## 2. 调度服务器部署 gateway

上传到调度服务器：

```text
dist/keyflow-gateway-prod.tar
.env.gateway
scripts/start_gateway_image_runtime.sh
```

启动：

```bash
chmod +x scripts/start_gateway_image_runtime.sh
./scripts/start_gateway_image_runtime.sh --load dist/keyflow-gateway-prod.tar
```

指定调度服务器对外端口：

```bash
./scripts/start_gateway_image_runtime.sh --load dist/keyflow-gateway-prod.tar --port 18001
```

替换旧容器：

```bash
./scripts/start_gateway_image_runtime.sh --load dist/keyflow-gateway-prod.tar --replace
```

调度服务只需要 `.env.gateway`。该文件会挂载到容器：

```text
宿主机 .env.gateway -> 容器 /app/.env.gateway
```

容器进程每次启动都会读取 `/app/.env.gateway`。修改 `.env.gateway` 后重启即可生效：

```bash
docker restart keyflow-gateway
```

端口说明：

- `.env.gateway` 中的 `PORT` 是容器内应用监听端口，默认 `8001`。
- `--port` 是调度服务器对外暴露端口，默认等于 `.env.gateway` 中的 `PORT`。
- `--host-port` 是 `--port` 的等价别名。
- Docker 端口映射在容器创建时确定。如果修改 `--port` 或 `.env.gateway` 中的 `PORT`，需要重建容器。

```bash
./scripts/start_gateway_image_runtime.sh --load dist/keyflow-gateway-prod.tar --port 18001 --replace
```

## 3. 子节点服务器部署 node

上传到每台子节点服务器：

```text
dist/keyflow-node-prod.tar
.env
config/
scripts/start_node_image_runtime.sh
```

启动：

```bash
chmod +x scripts/start_node_image_runtime.sh
./scripts/start_node_image_runtime.sh --load dist/keyflow-node-prod.tar
```

指定子节点服务器对外端口：

```bash
./scripts/start_node_image_runtime.sh --load dist/keyflow-node-prod.tar --port 18000
```

替换旧容器：

```bash
./scripts/start_node_image_runtime.sh --load dist/keyflow-node-prod.tar --replace
```

子节点会启动两个容器：

```text
keyflow-api
keyflow-worker
```

子节点配置挂载关系：

```text
宿主机 .env -> 容器 /app/.env
宿主机 config/ -> 容器 /app/config/
```

容器进程每次启动都会读取 `/app/.env`。修改 `.env` 后重启：

```bash
docker restart keyflow-api keyflow-worker
```

修改 `config/` 下文件后重启：

```bash
docker restart keyflow-api keyflow-worker
```

端口说明：

- `.env` 中的 `PORT` 是容器内 API 应用监听端口，默认 `8000`。
- `--port` 是子节点服务器对外暴露端口，默认等于 `.env` 中的 `PORT`。
- `--host-port` 是 `--port` 的等价别名。
- Docker 端口映射在容器创建时确定。如果修改 `--port` 或 `.env` 中的 `PORT`，需要重建容器。

```bash
./scripts/start_node_image_runtime.sh --load dist/keyflow-node-prod.tar --port 18000 --replace
```

## 4. 子节点连接调度服务

每台子节点服务器的 `.env` 需要配置调度服务器地址和注册密钥：

```env
GATEWAY_URL=http://gateway-server:8001
GATEWAY_REGISTER_KEY=change-me-gateway-register
NODE_ID=node-shanghai-01
NODE_DISPLAY_NAME=Shanghai Node 01
NODE_PUBLIC_BASE_URL=http://node-server:18000
NODE_TAGS=shanghai,telecom
NODE_HEARTBEAT_INTERVAL_SECONDS=30
```

`GATEWAY_REGISTER_KEY` 必须和调度服务器 `.env.gateway` 中的值一致。

`NODE_PUBLIC_BASE_URL` 必须是调度服务器能够访问到该子节点 `keyflow-api` 的地址。如果子节点使用了 `--port 18000`，这里也应该写对外端口 `18000`。

## 5. 子节点数据库和 Redis

子节点服务需要 PostgreSQL 和 Redis。生产环境建议在 `.env` 中显式配置真实地址：

```env
DATABASE_URL_READ=postgresql+asyncpg://user:password@postgres-host:5432/keyflow
DATABASE_URL_WRITE=postgresql+asyncpg://user:password@postgres-host:5432/keyflow
REDIS_URL=redis://redis-host:6379/0
```

如果子节点服务器本机也通过 Docker 部署 PostgreSQL/Redis，需要确保 `keyflow-api`、`keyflow-worker` 能访问对应主机名或地址。默认值仍和 compose 保持一致：

```text
DATABASE_URL_READ=postgresql+asyncpg://keyflow:keyflow@keyflow-postgres:5432/keyflow
DATABASE_URL_WRITE=postgresql+asyncpg://keyflow:keyflow@keyflow-postgres:5432/keyflow
REDIS_URL=redis://keyflow-redis:6379/0
```

## 6. 环境变量和 compose 的对应关系

原 compose 的 `env_file`：

```yaml
env_file:
  - ../../.env
```

tar 部署中不使用 Docker 的 `--env-file` 固化到容器创建配置，而是挂载 env 文件，由容器启动入口 `scripts/container_runtime.py` 在每次进程启动时读取。

这样做的结果：

- 修改 `.env.gateway` 后，`docker restart keyflow-gateway` 会读取新配置。
- 修改 `.env` 后，`docker restart keyflow-api keyflow-worker` 会读取新配置。
- 修改 `config/` 后，`docker restart keyflow-api keyflow-worker` 会读取新配置。
- 修改 `--port` 或端口 `PORT` 后需要 `--replace`，因为 Docker 端口映射不是进程内配置。

## 7. 日志轮转

启动脚本默认给容器加 Docker 日志轮转参数：

```text
--log-driver local
--log-opt max-size=100m
--log-opt max-file=3
```

这不是按天数清理，而是按大小轮转，避免容器日志无限增长。可以在启动脚本前用环境变量覆盖：

```bash
KEYFLOW_LOG_MAX_SIZE=200m KEYFLOW_LOG_MAX_FILE=5 ./scripts/start_node_image_runtime.sh --load dist/keyflow-node-prod.tar --replace
```

调度服务和子节点脚本都支持：

```text
KEYFLOW_LOG_DRIVER
KEYFLOW_LOG_MAX_SIZE
KEYFLOW_LOG_MAX_FILE
```

## 8. 检查

调度服务器：

```bash
docker ps --filter "name=keyflow-gateway"
curl http://127.0.0.1:8001/openapi.json
docker logs --tail 100 keyflow-gateway
```

子节点服务器：

```bash
docker ps --filter "name=keyflow-"
curl http://127.0.0.1:8000/health
docker logs --tail 100 keyflow-api
docker logs --tail 100 keyflow-worker
```

## 9. 停止

调度服务器：

```bash
docker stop keyflow-gateway
docker rm keyflow-gateway
```

子节点服务器：

```bash
docker stop keyflow-worker keyflow-api
docker rm keyflow-worker keyflow-api
```
