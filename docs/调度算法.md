# 四、你的算法：KeyFlow Score Scheduler

---

## 🔥 核心公式

```text
score =
  w1 * quota_score
+ w2 * idle_score
+ w3 * success_score
- w4 * error_penalty
- w5 * rate_limit_penalty
- w6 * cooldown_penalty
```

---

## 每一项解释（很关键）

### 1️⃣ quota_score（额度）

```text
= (quota_total - quota_used) / quota_total
```

👉 剩余越多 → 分数越高

---

### 2️⃣ idle_score（空闲度）

```text
= now - last_used_at
```

👉 越久没用 → 优先用

---

### 3️⃣ success_score（稳定性）

```text
= success_count / (success + error)
```

---

### 4️⃣ error_penalty（错误率）

```text
= error_rate * K
```

---

### 5️⃣ rate_limit_penalty（限流）

👉 如果429：

```text
= 高惩罚（直接降权）
```

---

### 6️⃣ cooldown_penalty（冷却）

```text
if now < cooldown_until:
    score = -∞（直接不可选）
```

---

# 五、调度流程（完整逻辑）

我给你一套**可以直接写代码的流程**

---

## 🔥 Step 0：输入

```json
{
  "provider": "openai",
  "model": "gpt-4"
}
```

---

## 🔥 Step 1：获取候选key

```text
Redis:
provider:openai:keys → ZSET
```

---

## 🔥 Step 2：过滤不可用key

```text
过滤：
- DISABLED
- COOLDOWN
- EXHAUSTED
```

---

## 🔥 Step 3：计算score

```python
for key in keys:
    score = calc_score(key)
```

---

## 🔥 Step 4：排序 / 选择

```text
选 score 最大的 key
```

👉 本质类似：

* 加权调度
* 动态负载均衡 ([GeeksforGeeks][1])

---

## 🔥 Step 5：原子锁定（关键）

```text
Redis Lua:
1. check key still valid
2. set last_used_at
3. return key
```

---

## 🔥 Step 6：返回给调用方

---

# 六、失败处理（核心机制）

## 🔥 1️⃣ 普通错误

```text
error_count++
score下降
```

---

## 🔥 2️⃣ rate limit（最重要）

```text
status → COOLDOWN
cooldown_until = now + backoff
```

---

👉 backoff策略：

```text
1min → 2min → 5min → 10min
```

---

## 🔥 3️⃣ quota耗尽

```text
status → EXHAUSTED
```

---

# 七、成功反馈（必须）

```text
success_count++
quota_used += tokens
last_used_at = now
```

---

# 九、最终算法总结（你可以写在README）

---

## KeyFlow Scheduling Algorithm

```text
1. 获取 provider 下所有可用 key
2. 过滤不可用状态
3. 计算动态 score：
   - quota
   - idle
   - error
   - rate limit
4. 选择 score 最大 key
5. Redis 原子锁定
6. 返回 key
7. 根据调用结果更新状态
```
