# 🧭 一、项目定位（必须先定死）

# ✅ 项目名称

**Account Pool Service（APS）**

# ✅ 系统角色

👉 **Provider Scoped Key Scheduling Service（资源调度子系统）**

---

# ✅ 在你整体架构中的位置

```text
Client
  ↓
AI Router（task gateway）
  ↓
Model-Forward（执行 work + provider fallback）
  ↓
🔥 Account Pool Service（你要做的）
  ↓
LLM Provider
```

---

# 🎯 核心职责（非常重要）

APS 只做三件事：

```text
1. Key调度（核心）
2. Key状态管理（限流 / 熔断 / 冷却）
3. Provider内资源优化（不是跨provider决策）
```

---

👉 ❗明确边界：

| 能力                | 是否属于 APS           |
| ----------------- | ------------------ |
| provider fallback | ❌（在 model-forward） |
| task routing      | ❌                  |
| model选择           | ❌                  |
| key调度             | ✅                  |
| key健康管理           | ✅                  |

---

# 🧱 二、架构设计（DDD + CQRS）

你之前选 DDD 是对的，我帮你定成“可落地版”：

👉 CQRS 可以显著提升读写性能与扩展性 ([GeeksforGeeks][1])

---

## 🔥 分层架构

```text
interfaces/        # FastAPI
application/       # 用例层（CQRS）
domain/            # 核心调度逻辑
infrastructure/    # Redis / DB / 插件
```

---

## 🔥 CQRS拆分（必须做）

### Command（写）

```text
- 添加key
- 禁用key
- 更新状态
- 上报错误
```

---

### Query（读）

```text
- 获取可用key（核心接口）
- 查询key列表
```

---

👉 好处：

* 读写分离
* Redis 专注高性能查询
* PostgreSQL 专注持久化

# 🧠 三、核心领域模型（重点）

## 🔥 1️⃣ Key实体

```python
class ApiKey:
    id: str
    provider: str
    key: str
    status: KeyStatus
    quota_total: int
    quota_used: int
    last_used_at: datetime
    error_count: int
    cooldown_until: datetime
```

---

## 🔥 2️⃣ Key状态机

```text
AVAILABLE
RATE_LIMITED
COOLDOWN
DISABLED
EXHAUSTED
```

---

## 🔥 3️⃣ 调度策略（核心）

```text
score =
  quota_remain_ratio
+ idle_time
- error_penalty
- rate_limit_penalty
```

---

# ⚙️ 四、Redis设计（高并发核心）

## 🔥 Key调度结构

```text
ZSET: provider:{provider}:keys
score → api_key
```

---

## 🔥 状态存储

```text
key_status:{key} → status
key_usage:{key} → usage info
key_cooldown:{key} → timestamp
```

---

## 🔥 原子调度（必须）

👉 Lua脚本：

```lua
-- 伪代码
1. 找最高score key
2. 判断状态
3. 更新 last_used_at
4. 返回 key
```

---

👉 ❗目的：

# 防止并发拿同一个key

# 🔄 七、与 Model-Forward 的交互流程

## 🔥 标准流程

```text
1. work执行
2. 调用 APS 获取 key
3. 发起请求
4. 成功 → report-success
5. 失败 → report-error
6. fallback provider（在 work）
```

---

## 🔥 时序图

```text
Model-Forward
   ↓
allocate-key
   ↓
APS返回key
   ↓
调用provider
   ↓
success / error
   ↓
report
```
